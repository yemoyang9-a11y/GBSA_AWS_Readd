# 관계 의미 파이프라인 독립 평가 — 2026-10-22

**판정: 로컬 구현과 제한된 실행 경로는 검증했다. 작업 전체 완료나 모든 소설에서의 의미 정확성은 입증하지 못했다.** 실제 모델 호출은 `401 invalid_api_key`로 출력이 없었고, 기존 운영 「탁류」 관계의 전체 재생성·검수·교체·공개도 수행되지 않았다.

이 문서와 평가 자료는 제품 구현에 참여하지 않은 평가 담당자가 작성했다. 제품 코드나 원격 DB는 수정하지 않았다. 평가 중 발견한 문제는 구현 담당자에게 전달하고 수정 후 같은 기대값으로 재실행했다.

## 1. 구현됨

- 의미 v2 계약에 감정/행동의 방향, 종류, 독립 관계 키, 구체적 설명, 사실·믿음·주장·소문·불확실·부정, 귀속 인물, 지속/사건, 활성/종료, 원문 인용·페이지·위치를 저장한다.
- 저장 endpoint를 정렬할 때 방향도 뒤집어 의미 주체를 유지한다. 같은 쌍의 서로 다른 관계와 반대 방향 감정, 반복 사건을 보존한다.
- 관계·양끝 인물·별칭·근거를 같은 cutoff의 SQL 선택 단계에서 제한한다(R4). 관계 조회와 UI 표시에는 런타임 모델 호출이 없다(R9).
- 구조 검증과 의미 검수를 분리한다. 의미 스냅샷에 검수 승인을 결합하고, 이미 공개된 자료를 변경하면 공개 상태를 먼저 무효화한다(R12).
- 전체 원문·장 범위·기존 인물 ID가 확인된 관계 스냅샷 교체 경로가 있다. 부분 산출물·다른 원문·미매핑 ID·다른 책 소유 ID는 거절한다.
- UI에서 방향, 설명, 인용, 부정·귀속·종료를 구분하고, bounded history로 과거 관계를 표시한다. 별칭은 공개 시점에 맞게 되감는다.
- 작품을 특정하지 않는 관계 추출 runner와 규칙은 있다. 이것만으로 실제 모델 산출 품질이 확인된 것은 아니다.

「탁류」 외의 실제 작품은 Jane Austen의 공개 도메인 「Pride and Prejudice」다. GitHub GITenberg 원본 URL, SHA256, 행 범위는 `austen-holdout-source.json`에 있다. Austen의 `page 1`은 발췌 fixture 번호이며 책의 실제 첫 페이지가 아니다. 「유리 항구」「안개 실험실」「역 앞의 우산」은 이 평가를 위해 만든 창작문이다.

독립 oracle는 구현 결과를 보기 전에 원문으로 정했으며 총 25사례다. 다만 평가 중 fixture와 실패 사례를 구현 담당자에게 공유했다. 특히 Austen belief의 보류 수정 후 재실행은 이제 회귀 검사이며 새로운 blind holdout 검증이 아니다. 다른 holdout 표기도 구현 초기의 별도 출처라는 뜻으로, 최종 실행 시까지 비공개였다는 뜻은 아니다. 그중 21개는 올바른/잘못된 fact 후보를 주입하여 경계를 검사했다. **잘못된 의미 후보 11개가 구조 검증을 여전히 통과한다.** 반대 방향, 부정, 문장 속 단순 동시 등장, 사물 욕망의 전이, 귀속 생략 등이다. 이 값은 실제 모델 오류율이 아니다. 구조 검증기를 의미 정답 판정기로 간주할 수 없다는 반례이며, 통과 후보도 별도 사람 검수가 필수다. 해당 후보들이 사람 검수 없이 공개되지 않는 R12 경계는 위 7개 SQL 검사로 별도로 검증했다. `results/current-candidate-probes.json`에 잘못된 주입과 기대 사실을 그대로 보존했다.

평가 중 실제로 발견하고 재검증한 문제는 다음과 같다.

- 오래된 검수 승인이 변경된 의미를 승인하지 않도록 스냅샷을 결합하고, 공개된 자료의 재등록 시 공개 상태를 무효화했다.
- 전체 교체에서 다른 책의 관계 ID를 주면 그 책의 행이 덮이는 문제를 재현했다. 소유권 선검사와 원자적 upsert 보호 후 같은 반례가 변경 전 거절된다. 수정 전 결과도 `results/snapshot-replacement-before-owner-fix.json`에 보존했다.
- 과거 시점에 늦게 확인된 별칭이 보일 수 있는 문제를 확인하고, 날짜가 있는 별칭은 시점으로 필터링하는 실행을 검증했다.
- 모바일 크기에서 긴 인물 이름과 조작 버튼이 겹치는 모습을 확인했다. 별도 조작 영역으로 옮긴 뒤 실제 bounds와 이미지로 다시 확인했다.
- Austen의 적절한 귀속 문장 “여긴다”가 보류되는 경우를 확인했다. 기대 문장을 바꾸지 않았으며 수정 후 원문→저장→UI 흐름을 통과했다.

## 3. 구현 안 됨 / 이번 작업에서 미적용

- 사람 검수를 대체하는 자동 의미 정답 판정기는 구현되지 않았다. 정확한 인용과 구조 적합성만으로 방향·관계 해석을 증명하지 않는다.
- 기존 운영 「탁류」 전량의 의미 v2 재생성·검수·교체·공개는 미적용이다. 과거 `욕망` 라벨이나 저장 순서를 현재 코드가 자동으로 정답 방향으로 바꾸지는 않는다. 기존 자료는 방향 미검증으로 취급한다.
- 실제 전체 작품에서의 추출 누락률·방향 정확도·별칭 연결 정확도·관계 전환 누락을 측정한 성적표는 없다. 원문 2개에서 목표 주장 6개를 사람이 작성한 검사는 그 지표를 대신하지 못한다.

## 4. 환경 이슈로 검사가 제한됨

- 실행 담당자의 기존 LLM gateway를 통한 실제 모델 시도는 `401 invalid_api_key`로 실패하여 모델 출력이 없었다. 모델의 원문→후보 생성, 실출력 보류율, 실제 오답·누락률은 **미검증**이다. 평가 담당자는 키 발급이나 외부 API 재호출을 대신 진행하지 않았다.
- SQL 실행은 PGlite의 로컬 PostgreSQL WASM이었다. 관계와 무관한 vector 확장/임베딩 컬럼은 baseline에서 제외했다. 원격 운영 DB migration·등록·HTTP 관통 검증이 아니다.
- UI 실행은 실제 제품 컴포넌트와 브라우저 Chromium을 사용했지만 운영 앱 배포나 실기기/Safari 검증이 아니다. 인물 ID는 독립 fixture에서 알려진 대상으로 공급했으므로 전체 인물/별칭 추출 경로도 별도 검증이 필요하다.

현재 증거는 “재사용 가능한 의미 계약·검수·저장·조회·표시 경로가 로컬에서 작동한다”는 판정을 지지한다. “어떤 소설도 정확하게 자동 추출한다” 또는 “기존 운영 인물관계도가 모두 고쳐졌다”는 판정을 지지하지 않는다.
