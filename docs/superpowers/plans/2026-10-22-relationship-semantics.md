# 인물관계도 생성·검증 개선

목표: 검증한 원문 범위에서 누가 누구에게 어떤 관계인지, 해당 시점과 불확실성이 화면까지 보존되는지 확인한다. 특정 작품의 단어 치환으로 처리하지 않는다.

## 조사 결과와 설계

- 탁류 p91 김씨 → 초봉이 질투, p129 형보 → 초봉이 탐냄: 기존 단어 라벨과 UUID 정렬만으로 방향을 복원할 수 없다.
- 같은 쌍의 최신 1행 선택은 질투와 중매 같은 동시 관계를 소실한다.
- 정확한 인용 검사는 출처 일치 검사이며, 관계 의미가 원문에 부합한다는 증명이 아니다. 공개 전 의미 검수와 독립 원문 평가가 필요하다.
- v2 관계 의미(JSONB)에 방향·관계 종류/추적 키·설명·확정 여부/귀속·단발/지속·상태·원문 인용/위치를 저장한다. 정렬 시 방향도 뒤집는다.
- 읽은 범위로 관계/인물/근거를 먼저 제한한다. 최신 선택은 의미별 이력에 적용하고, 제한된 과거 이력을 함께 내려 되감기를 복원한다. 미래 종료 페이지를 미리 노출하지 않는다.
- 기존 데이터는 방향을 추정하지 않고 미검증이라고 표시한다. 생성 캐시 버전을 변경하고 변경된 콘텐츠의 검수 승인을 재사용하지 않는다.

## 작업 분담

- root: 공통 계약, SQL migration, 조회/API, 실행 통합, 보고.
- relationship_pipeline: 생성/근거 검증/병합/등록/검수/캐시와 관련 테스트.
- relationship_runtime_ui: 관계도 방향/복수선/문구/근거/되감기, 모바일 회귀.
- relationship_evaluator: 제품 코드에 참여하지 않고 원문 oracle·held-out·최종 평가. 구현자가 자기 결과를 승인하지 않는다.

## 검증 계획

1. 수정 전 원문과 후보 주입 검증 결과를 보존한다.
2. 단위 테스트: 방향 반전, 동시 관계, 변경/단발, 근거·인물 시점 경계, 기존 데이터 호환.
3. 별도 로컬 PostgreSQL 엔진에서 migration/등록/조회 실행, 실제 SQL로 저장 의미와 cutoff 확인. 원격 DB에는 쓰지 않는다.
4. gateway를 통한 실제 모델 발췌 생성: 탁류와 독립 평가자가 고른 Austen 원문. 모델 미사용 주입 검사와 구분한다.
5. 응답→실제 브라우저 그래프: iPhone/Android/iPad/PC 크기에서 방향·상세·근거·되감기·전체화면·터치 확인.
6. 독립 평가자가 생성 결과와 원문을 비교하고 존재/인물/방향/구체성/시점/근거/스포일러/누락·보류를 평가. 실패 수정 후 재평가.

네 상태: 구현됨 / 실제 검증됨(범위 명시) / 구현 안 됨 / 환경 이슈로 검사가 제한됨. 환경상 못 한 실제 기기·원격 운영 검증은 통과로 계산하지 않는다.
