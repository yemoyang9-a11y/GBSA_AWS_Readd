# 인물 근거 검증과 독서 범위 대화 개선
사용자 요청(2026-10-21)과 후속 요청(2026-10-22)을 구현 기준으로 사용한다. 작업 브랜치는 yemo-develop이다. 2026-10-22 사용자는 PR 작성, CI/CD 확인, 병합, 운영 테스트까지 명시적으로 승인했다. 전체 도서 재처리는 범위 밖이며, 운영 데이터 변경은 아래 승인된 2행 교정으로 제한한다.

## 목표
원문 기반 인물의 오탐·누락·별명 중복을 줄이고, 읽은 범위에서 확인된 부분을 자연스럽게 답한다. 근거 없음·검색 실패·시스템 오류·검증된 부재를 혼동하지 않는다. 작품 전체 부재는 일부 검색 결과나 완독 여부만으로 단정하지 않는다.

## 불변 조건
서버 getCutoffSnapshot이 유일한 상한 원천이다. 원문·요약·속성·관계·별칭·캐시·대화 기록·화면 표시까지 적용한다. 미래 사실이나 공개 여부를 암시하지 않는다. 인용문은 사용자 입력이라는 이유만으로 사실 근거가 되지 않는다.
기존 CLAUDE R10 고정 문구 및 D14 완독 부재 단정은 이번 명시적 요청으로 대체한다. 타 파트 수정도 이번 요청의 범위에 포함된다. LLM 게이트웨이와 데이터 선택 단계의 cutoff 강제는 유지한다.

## 인물
사물 형태의 이름도 인물일 수 있다. 인물·별칭 대응·노트·관계마다 원문 인용과 위치를 검증한다. 모호한 일반 호칭을 임의의 첫 인물로 매핑하지 않는다. 미확인 후보는 검수용으로 보존하고 자동 공개하지 않는다. 사전 기반 일괄 삭제를 사용하지 않는다.

## 대화
부분 근거는 살리고 확인하지 못한 속성만 제한한다. 감상·인사·일반적인 단어 설명은 작품 사실과 구분한다. 검색 0건으로 부재 단정 금지. 검색 장애는 오류로, 임베딩 장애는 동일 cutoff의 텍스트 검색으로 회복 가능하다. 이전 큰 cutoff의 화면·스트림·기록은 페이지 이동 후 재사용하지 않는다.

## 평가
실제 저장소 탁류 원문과 가상 사례를 구분한다. 원문 hash와 split 위치를 기록한다. negative/positive 경계 쌍, 중복/모호 호칭, 미발견/장애, 위조 인용, 되감기·늦은 SSE를 회귀 검증한다. 고정 문자열 정답 대신 근거 선택 및 정책·표시 동작을 검사한다. 실 DB·실 LLM을 실행하지 못하면 그 한계를 분리 보고한다.

## 2026-10-22 후속 범위
사용자가 승인한 운영 데이터 변경은 전봇대 노트 1행의 source_page와 관계 1행의 established_page를 303에서 304로 교정하는 것뿐이다. 원문·인물 첫 등장은 유지한다. 별도 발견한 외모 문구 별칭 1행은 백업/교정안만 준비하고 미적용으로 남긴다.

Anthropic 크레딧 소진 이후 사용자가 OpenAI API 키 발급·교체 및 실제 모델 테스트를 승인했다. 기본 provider는 OpenAI Responses API이고, 모델은 `gpt-6-luna`, 추론 수준은 `low`다. 사용자가 비용과 첫 응답 지연을 이유로 검토 모델을 명시적으로 제외했으므로, 챗봇은 정상 답변당 생성 모델을 한 번 호출하고 생성되는 텍스트를 즉시 스트리밍한다. 검토 모델, 전체 답변 전송 보류, 자동 답변 재생성은 사용하지 않는다. 전송 오류에 대한 SDK 재시도는 별개다.

검색·근거 조립·인용 대조·이력의 cutoff 제한은 유지한다. 모델이 생성한 내부 제어 토큰과 시스템 오류는 오류로 전파하며, 실패한 부분 답변은 대화 이력에 저장하지 않는다. 운영 배포와 실제 질문 테스트까지 수행하되, 로컬 테스트 통과만으로 운영 반영 완료를 선언하지 않는다. 이전 검토 모델 실험 기록은 과거 보고서로 보존하며 현재 동작의 근거로 사용하지 않는다.
