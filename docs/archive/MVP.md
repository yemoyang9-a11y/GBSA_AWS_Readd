## 1. MVP 목표

**독자가 읽던 소설을 다시 펼쳤을 때, 검색이나 되돌아 읽기 없이 안전하게 이어 읽을 수 있는 서비스를 완결된 형태로 만든다.**

- 검증 가설: *독자가 보고 있는 화면을 공통 기준점으로 삼으면, 리캡·인물·관계·용어·타임라인이 하나의 맥락으로 연결된다.*
- MVP는 기능을 덜어낸 시제품이 아니라 **핵심 경로가 끝까지 동작하는 서비스**다. 덜어내는 것은 부가 정보 기능과 일부 예외 처리이며, 핵심 경로에서는 어떤 단계도 비워두지 않는다.
- 판정은 두 축이다. **릴리스 게이트** + **5장 완료 조건**(게이트가 다루지 않는 P0 요구 포함).
- 품질 원칙은 하나다. 기능이 하나 덜 붙는 것보다 스포일러가 한 번 새는 쪽이 실패에 가깝다. 단, 전부 차단하는 구현도 실패다(NFR-REL-001·002 쌍 판정).
**위치 표현 규칙** — 내부 기준은 페이지, 사전 생성 단위는 장, 사용자에게 보이는 값은 화면에 따라 다르다.

| 화면 | 표시 |
| --- | --- |
| 읽기 화면 | **페이지 번호만** ("12 / 340"). 진도 바를 두지 않는다 |
| 브리핑 | 진도 바 + % + 목차상 현재 장 |
| 대시보드 | 진도 바 + % (읽던 도서에만) |

%는 전체 페이지 수 대비 현재 페이지로 계산하며 별도 저장 값을 두지 않는다. **세 화면 모두 현재 위치를 기준으로 하며 최대 도달 값을 따로 두지 않는다**(FR-BRF-005 🚦).

**범위 판단 근거 5가지**

1. **MVP-05는 P0다.** MVP-03 게이트의 4개 검증 케이스 중 하나가 목차 이동이다. 목차가 없으면 케이스를 실행할 수 없어 P0 게이트를 판정할 수 없다. P1로 두면 일정 압박 시 먼저 떨어져 나가면서 게이트를 함께 무너뜨린다.
2. **MVP-09는 세션 종료 시 1건만 미리 만든다 (8/18 확정).** 사용자가 읽기를 마치면 그 시점 기준점의 리캡을 자동 생성해 저장하고, 다음 접속의 브리핑에서 대기 없이 표시한다. 기준점이 달라진 요청(읽는 중 싸비 리캡)은 실시간 생성이다. **브리핑 진입(MVP-39)이 리캡의 주 경로이므로 시연 동선에서는 저장분이 사용되며, 발표 중 실시간 호출이 발생하지 않는다.** 데모에서는 시연 위치의 저장분을 관리자가 미리 넣어둔다(MVP-21). **세션 종료는 무조작 30분으로 판정한다(8/18 확정).** 30분 이내 재진입은 같은 세션이므로 **브리핑을 건너뛰고** 읽던 페이지로 직행하고, 30분 경과 후 재진입은 새 세션이므로 브리핑에서 미리 만들어 둔 리캡이 표시된다. **브리핑이 뜨는 조건과 리캡이 준비된 조건이 같아서 브리핑에서 LLM 호출이 발생하지 않는다.**
3. **MVP-20은 UI 없이 데이터만 만든다.** 생성·검수는 도서 단위 배치로 한 번에 도는 작업이라, 나중에 용어·사건만 따로 돌리면 배치와 검수 사이클을 한 번 더 치러야 한다.
4. **MVP-26·37은 기능이 아니지만 범위에 넣는다.** 통신 암호화, 학습 미사용, 저작권, 개인정보 고지, 접근성은 게이트에 없다는 이유로 범위표에서 빠지면 아무도 하지 않는다. 특히 관계도 색상 의존 제거는 관계도(P0)를 만든 뒤에 손대면 렌더링 로직을 다시 건드려야 한다.
5. **MVP-30은 기능이 아니라 표기만 제외한다.** 동명이인 분리 로직(MVP-13)은 게이트다.
6. **MVP-33(챗봇)은 8/18 승격분이며, 이 개정에서 비용이 가장 크다.** 싸비 탭이 3개로 줄면서 리캡·관계도만 남는 구성을 보완하고, 삭제한 배경지식 탭의 재열람 경로를 겸한다. 다만 딸려오는 것이 많다 — **NFR-SEC-006이 P0 🚦로 복원**되고(v0.4에 걸어둔 조건이 발동), **챗봇의 근거 검색 구조를 아키텍처 문서에서 새로 설계해야 하며**, 릴리스 게이트가 25개에서 30개로 늘고, 스포일러 리그레션 30건에 챗봇 케이스가 추가된다. **정답셋 담당이 아직 미정인 상태에서 검증 부하가 늘어난다는 점을 인지하고 결정한 것이다.** — *8/19 후속: 근거 구조는 아키텍처 1회차에서 B-1로 확정, NFR-SEC-006 판정 기준도 확정. NFR-AVL-003을 게이트에서 내려 게이트는 **29개**가 됐고, 정답셋은 담당·기한을 미결로 두지 않고 기능 구현 후 팀 자체 진행으로 정리했다.*
7. **MVP-39는 대시보드·리캡·목차에 모두 걸린다.** 브리핑은 새 화면이지만 안에 들어가는 것은 이미 P0인 기능들(리캡·목차·진도 표시)의 조합이다. 새로 만드는 것은 화면과 진입 흐름이며, 이것이 P0인 이유는 **리캡의 주 진입 경로가 여기로 옮겨왔기 때문**이다. 브리핑이 없으면 재개 동선에서 리캡을 마주할 자리가 사라진다.

| MVP-S03 | 대시보드에서 표지의 `i`를 눌러 책 소개와 배경지식을 확인한 뒤 도서를 고른다 | Flow C | MVP-15·16·01 |
| MVP-S04 | 목차로 앞 장에 다녀오거나 계속 읽어 나갈 때, 싸비 정보가 화면을 따라 즉시 늘고 줄어든다 | Flow A·B·D | MVP-03·05·06·12·14 |

**MVP-S04가 스포일러 안전성의 사용자 경험을 담당한다.** 싸비를 연 채 페이지를 넘기면 없던 인물이 노드로 추가되고(FR-SVB-003), 목차로 앞 장에 다녀오면 정보가 그 시점 기준으로 줄어든다(FR-NAV-001).

**8/18 챗봇이 P0으로 올라오면서 두 번째 경로가 생겼다.** 읽지 않은 부분을 물으면 근거가 없어 안내 문구가 반환된다(FR-QNA-004). 다만 그 문구는 대상이 뒤에 나오는지 작품에 아예 없는지를 판별하지 않으므로, **거절 자체가 정보가 되지 않는다.** 판별하는 순간 그 결과가 응답 차이로 새어나가기 때문이다.

차단이 거절 메시지가 아니라 **정보의 증감**으로 드러나는 방식이며, 사용자에게는 이쪽이 덜 방해된다. 무엇을 막고 있는지 설명하지 않아도 읽은 만큼만 보인다는 사실이 그대로 전달된다.

## 6. MVP 핵심 성공 기준

**MVP 성공 = 릴리스 게이트 전부 통과 + 5장 완료 조건 충족.** 수치 목표는 NFR에 정의되어 있으므로 여기서 반복하지 않는다.

| 지표 | 측정 기준 | 목표 |
| --- | --- | --- |
| 게이트 통과율 | 릴리스 게이트 중 통과 수 | **전량** |
| 정답셋 종속 게이트 해제 | NFR-AI-008 완료로 판정 가능해진 게이트 수 | 10 / 10 (8/22까지) |
| 완료 조건 충족률 | 5장 네 블록의 체크 항목 | 100% |
| 핵심 경로 안정성 | MVP-S01~S04 무중단 실행 | 3회 연속 |
| 범위 이탈 | Freeze 이후 추가된 기능 수 | **0건** |
| 미완비 도서 오진입 | 미완비 도서 진입 시도 시 차단 실패 건수 | 0건 |

> 리캡 사용률·재개율 같은 사용자 행동 지표는 실사용자 데이터가 쌓이는 시점에 정의한다. 지금 목표치를 두면 근거 없는 숫자가 된다.
