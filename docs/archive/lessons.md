## 2026-08-19 — 마크다운 표 행이 여러 줄에 걸쳐 있어 행 단위 파싱이 틀린다

**증상** — FR 조항 건수를 세려고 `FR_NFR.md`의 표를 줄 단위로 파싱했더니 **P0 56 / P1 12 / P2 6 / 합계 74**가 나왔다. 문서에 기재된 값(합계 76)과 2건 어긋났고, `FR-ERR-002a`·`FR-ERR-002b`가 "우선순위 셀이 없음 = 삭제된 조항"으로 잘못 분류됐다.

**원인** — 이 저장소의 표에는 **한 행이 물리적으로 여러 줄에 걸친 셀**이 있다. 예를 들어 `FR-ERR-002a` 행은 요구사항 셀 안에서 줄바꿈이 일어나, 우선순위 `P1`이 두 번째 물리 줄에 있다. `line.startswith('| FR-')`로 행을 잡으면 첫 줄만 읽게 되어 뒤쪽 셀을 통째로 놓친다. AC 셀에 `①②③`을 줄바꿈으로 나열한 행들이 전부 같은 구조다.

**검증된 해결책** — 두 줄 이상에 걸친 행을 하나로 합친 뒤 세거나, 파싱 결과를 문서 기재값과 대조해 차이 나는 ID를 직접 확인한다. 이번에는 후자로 처리했다: 누락된 두 건이 `FR-ERR-002a/b`임을 확인하고 P1에 더해 **P0 56 / P1 14 / P2 6 / 합계 76**으로 확정했고, 접두어별 집계(ERR 7)와 총합이 맞아떨어지는 것으로 교차 확인했다.

**교훈** — 조항 수·게이트 수처럼 여러 문서에 퍼져 있는 수치는 눈으로 세지 말고 스크립트로 세되, **스크립트 결과를 그대로 믿지 말고 접두어별 합계 같은 독립적인 방법으로 한 번 더 맞춰본다.** 이 저장소는 같은 수치가 FR/NFR·MVP·PRD·B안 4곳에 중복 기재되어 있어, 한 번 틀리면 네 곳이 같이 틀린다.

**관련 파일** — `FR_NFR.md` 1.16절(FR 건수), 3장(릴리스 게이트 29개)

## 2026-08-19 — GFM 표 셀 안의 파이프는 백틱 안에 있어도 셀을 쪼갠다

**증상** — 아키텍처 문서 4.2절 API 표에 `` `{route: briefing | reader, page}` `` 를 그대로 넣었다.

**원인** — GitHub Flavored Markdown은 표의 행을 **인라인 파싱보다 먼저** `|`로 자른다. 따라서 인라인 코드(백틱) 안에 있어도 파이프는 셀 구분자로 먹혀서 해당 행에 열이 하나 더 생기고 뒤쪽 셀이 밀린다.

**해결책** — `\|` 로 이스케이프한다. 화면에 보이는 글자는 `|` 그대로다. 이 저장소는 문서가 전부 표 중심이라 API 시그니처·타입 유니온·정규식을 표에 넣을 때 반복될 위험이 있다.

**검증 수준** — GFM 스펙에 따른 처리이며 이스케이프를 적용했다. **브라우저 렌더링으로 직접 확인하지는 않았다.** 다음에 GitHub에서 해당 표를 볼 일이 있으면 한 번 확인해 둘 것.

**관련 파일** — `architecture-r1.md` 4.2절

## 2026-08-19 — Bash 도구에 PowerShell here-string(`@'...'@`)을 쓰면 커밋 메시지에 `@` 줄이 섞인다

**증상** — 명세서 파일명 rename을 커밋했더니 제목이 `@ docs: 명세서 파일명 영문화 — ...` 로 나왔다. `git log -1 --format='%B' | cat -A` 로 확인하니 메시지 **첫 줄이 `@` 한 글자**, 마지막 줄에도 `@` 가 하나 더 붙어 있었다.

**원인** — 이 환경에는 셸이 둘(PowerShell, Bash) 있고 여러 줄 문자열 문법이 서로 다르다. PowerShell here-string 문법 `@'...'@` 를 **Bash 도구에** 그대로 썼더니, bash는 이것을 here-string이 아니라 문자열 연결(`@` + 작은따옴표 문자열 + `@`)로 해석했다. 그래서 앞뒤의 `@` 가 메시지 본문에 그대로 들어갔다. 문법 오류가 아니라 **조용히 통과하는** 점이 위험하다 — 커밋은 성공하고 메시지만 오염된다.

**검증된 해결책** — Bash 도구에서는 heredoc을 쓴다. `git commit -F - <<'EOF' ... EOF` 형태가 안전하다(`'EOF'` 처럼 따옴표로 감싸야 `$`·백틱이 확장되지 않는다). 이번에는 아직 push 전이라 `git commit --amend -F - <<'EOF'` 로 메시지만 고쳤고, `git log -1 --format='%B'` 로 `@` 가 사라진 것을 확인했다.

**교훈** — 커밋 후 메시지를 눈으로 확인한다. `git log --oneline` 한 줄만 봐도 이번 오염은 바로 보였다. 그리고 여러 줄 문자열을 넘길 때는 **지금 쓰는 도구가 PowerShell인지 Bash인지 먼저 확인한다.** 반대 방향(PowerShell에 heredoc)도 같은 함정이다.

**관련 커밋** — `bd68f0f` (amend 전 `1850dc1`)
