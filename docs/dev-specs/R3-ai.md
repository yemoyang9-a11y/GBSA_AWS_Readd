## 1. ⚡ 최우선 — 8/19 오전, 최소 게이트웨이

**R1과 R2가 당신을 기다린다.** 4.3절이 "④⑤⑦ → ⑥, LLM 호출은 게이트웨이 경유만 허용"으로 못 박고 있어서, R1의 생성 6종도 당신 코드를 거친다. **당신이 늦으면 크리티컬 패스인 R1이 멈춘다.**

8/19 오전에 내놓을 최소 버전:

```
call(task, prompt) -> response       // 호출 + 재시도 + 응답 반환
```

**나중에 붙여도 되는 것** — 작업별 모델 매핑, 호출량 상한, 스트리밍, 토큰 계측. 이것들이 없어도 R1·R2는 진행할 수 있다.

> R1이 **임베딩 호출도 게이트웨이 경유인지** 물어올 것이다. 4.3절 규칙은 "LLM 호출"을 대상으로 하는데 임베딩 포함 여부가 문서에 없다. 합의하고 결과를 기록한다 — 지어내지 말 것.

## 3. 챗봇 근거 조립기 `8/20` — 이 역할의 핵심

### 조립 함수의 시그니처가 방어선이다

```
근거조립(bookId, K) -> 근거블록          ← 질의 텍스트를 인자로 받지 않는다
```

**질의 텍스트를 인자로 받는 순간 NFR-SEC-006 🚦의 1차 방어선이 무너진다.** 인젝션이 LLM 설득에 성공하더라도 **LLM이 보고 있는 것 자체가 기준점 이하 데이터뿐**이어야 한다(5.4절). 조립이 끝난 뒤 프롬프트의 사용자 턴에만 질의가 들어간다.

### 근거 구성 (FR-QNA-006 🚦)

```
질의 → 기준점 스냅샷 K 확보 (질의 시점 고정, UC-27 A5)

→ ① 전량 주입분 (질의 비관여, 결정적)
     ①-a 장 요약 전부        (종료 페이지 <= K)
     ①-b 현재 장 원문 절단   [현재 장 시작 .. K]
     ②   엔티티 전량 — 인물·별칭·관계·인물 노트·용어·사건 (각 <= K)
          · 관계는 이력 전체를 확립 페이지와 병기해 투입 (A6)
     ③   배경지식 전문       (상한 없음 — R5)

→ ④ 검색 청크 N개 (질의 관여, 범위는 여전히 K로 강제)
     질의 정규화(별칭 사전으로 대표명 치환) → 질의 임베딩
     WHERE page_no <= K  ORDER BY 유사도  LIMIT 6      ← 사전 필터

→ 모델 선택: 규칙 기반 난이도 판정            ← 범위 비관여, 호출 수 불변
→ LLM 1회 (스트리밍, NFR-PERF-008)
→ 근거 부재 토큰 감지 → 서버 상수 문구 치환 (FR-QNA-004 🚦)
→ 로그: K, 투입 레코드 ID 전수 + 검색 선정 페이지·스코어 + 선택 모델 (NFR-OBS-005 🚦)
```

**관계 투입은 표시와 규칙이 다르다** (A6) — 관계도(R4)는 최신 라벨 1개만 표시하지만, **챗봇 근거에는 이력 전체를 확립 페이지와 병기해 넣는다.** 변화 자체가 답이 되는 질의에 대응하기 위해서다. 페이지 병기가 없으면 모델이 옛 라벨과 새 라벨을 혼동한다.

### 벡터 검색 — 사전 필터가 필수

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 필터 시점 | **유사도 계산 이전** (사전 필터) | 사후 필터는 결과 고갈·순위 왜곡·우회 표면을 만든다 |
| 조건식 | `page_no <= K` | 조회형·리캡과 **완전히 같은 조건식**. 강제 지점이 늘지 않는다 |
| top-N | **6 고정** | 검색분 프롬프트 예산 ≈ 6,000자. 탐색적 테스트에서 앞 장 원문 세부 질의가 **반복 실패할 때만** 상향 (6.4절) |
| 청크 단위 | **페이지 1장** | 별도 청크 테이블 없음. 페이지 경계 문제가 구조적으로 발생하지 않는다 |
| 중첩 | 없음 | 페이지 1:1 |

**검색은 단일 SQL로 끝나야 한다.** 상한 조건이 쿼리문에 그대로 드러나는 것이 강제의 가시성이다(5.3절).

### 난이도 분기 — 규칙 기반 (D13 ②)

**LLM 라우팅을 만들지 않는다.** 판정을 LLM에 시키면 질의당 호출이 2회가 되어 R9(런타임 호출 2종)와 NFR-PERF-008 예산이 함께 흔들린다.

**판정 규칙의 내용은 문서에 없다 — 당신이 구현하며 정한다.** 지켜야 할 조건은 둘뿐이다.

1. 판정이 **근거 조립 범위에 관여하지 않을 것** — 질의 텍스트는 "무엇을 고르나"(검색)에만 관여하고 "어디까지 보나"(상한)에는 관여할 경로가 없어야 한다 (NFR-SEC-006 🚦)
2. **선택된 모델을 질의 로그에 기록**할 것 (NFR-OBS-005 🚦)

### 근거 부재 처리 (FR-QNA-004 🚦) — 무판별이 구조로 성립해야 한다

- 시스템 규칙에 **근거 부재 토큰 규약**을 둔다
- 서버가 토큰을 감지해 **보유 상수 문구로 치환**한다 → 문구 동일성이 기계적으로 보장된다
- 확정 문구: `현재까지 읽은 페이지 기준으로 알 수 없는 내용입니다. 다른 질문 해주세요.`
- 같은 신호를 질의 로그의 '근거 부재 여부'에 기록한다

**"대상이 기준점 이후인가 / 작품에 없는가"를 판별하는 코드를 만들지 않는다.** 시스템 어느 경로도 기준점 초과 데이터에 접근하지 않으므로 **판별할 능력 자체가 없다** — 그게 이 조항이 성립하는 방식이다(5.4절 3번).

### 프롬프트 구성

```
[시스템 규칙 + 근거 부재 토큰 규약]
[근거 블록 — 데이터 태그로 감쌈]      ← 지시·데이터 분리 (2차선 방어)
[대화 이력 — P1]
[사용자 질문]
```

시스템 규칙에 **근거 외 생성 금지**(NFR-AI-005)를 둔다. 이것이 A10(모델의 사전 지식 누설)에 대한 **유일한 수단**이며 100% 보장이 아니다 — 구조적 해결책을 지어내지 말 것.

## 4. 결합 지점

### 🔗 R2의 기준점 스냅샷 (8/19 시그니처, 구현은 나중)

시그니처만 나오면 **스텁 3줄로 진행**한다. R2의 구현을 기다리지 않는다.

### 🔗 R1의 실데이터 + 임베딩 (8/21)

그전까지 시드로 진행. **시드의 임베딩은 직접 만들어야** 검색 경로를 테스트할 수 있다 — R1의 적재 스크립트를 기다리지 말고 시드 20~30페이지에 대해 임베딩을 한 번 돌려둔다.

### 🔗 R1이 넘겨주는 성능 예산 입력 (CP1, 8/19 저녁)

**가장 긴 장의 원문 절단 최대 크기.** 이게 B-1 프롬프트의 최악값이고 NFR-PERF-008 예산 계산의 입력이다. 받으면 프롬프트 총량을 계산해 둔다.

### 🔗 R4가 소비하는 것

`POST /books/{b}/chat` (SSE). 스트리밍 형식을 R4와 맞춘다.

## 5.5 자가 검증 — 이 파트는 테스트가 곧 게이트 판정이다

CP5의 인젝션 10건은 사후 판정이다. **개발 중에는 아래를 매 세션 돌린다.**

### 구조 검증 (정적 — 가장 중요)

| # | 확인 | 조항 |
| --- | --- | --- |
| 1 | **근거 조립 함수 시그니처에 질의 텍스트 인자가 없다** | NFR-SEC-006 🚦 |
| 2 | 조립·검색의 상한 인자가 **기준점 결정기 반환값에서만** 온다 | NFR-SEC-006 판정 ① |
| 3 | 게이트웨이를 거치지 않는 LLM 직접 호출 0건 | 4.3절 |

1번은 **컴파일·린트 수준에서 강제된다.** 인자가 없으면 질의로 범위를 바꿀 방법이 물리적으로 없다.

### 근거 범위 (FR-QNA-006 🚦)

| # | 테스트 |
| --- | --- |
| 4 | 투입된 장 요약이 전부 `종료 페이지 <= K` |
| 5 | 투입된 엔티티(인물·별칭·관계·노트·용어·사건)가 전부 `<= K` |
| 6 | **배경지식은 K와 무관하게 전량 투입** (상한 예외 — R5) |
| 7 | **같은 K에서 질의를 바꿔도 전량 주입분이 동일** ← 질의 비관여의 증명 |

7번이 이 파트의 핵심 테스트다. 질의를 10개 바꿔 돌려도 ①②③이 완전히 같아야 한다.

### 검색 — 사전 필터 (5.3절)

| # | 테스트 |
| --- | --- |
| 8 | 검색 결과에 `page_no > K`인 페이지 **0건** |
| 9 | **negative + positive 쌍** — K=40에서 p.120 내용이 검색되지 않고, K=130에서는 검색된다 |
| 10 | 결과 개수 <= 6 (top-N) |
| 11 | K가 작아 후보가 6개 미만이어도 오류 없이 동작 |

9번의 positive가 없으면 "검색이 항상 빈 결과를 반환해도" 8번이 통과한다.

### 근거 부재 문구 (FR-QNA-004 🚦)

| # | 테스트 |
| --- | --- |
| 12 | 근거 부재 시 응답이 확정 문구와 **문자 단위로 완전 일치** |
| 13 | 서로 다른 3가지 부재 상황(기준점 이후 / 작품에 없음 / 무관한 질문)에서 **모두 같은 문구** |
| 14 | 질의 로그의 '근거 부재 여부'가 `true`로 기록 |

13번이 무판별의 검증이다. 상황별로 문구가 달라지면 그 자체가 판별 능력을 드러낸 것이다.
