# R4 — 프론트엔드·조회 개발 명세서

**담당 컴포넌트** ① 콘텐츠 조회 + ③ 싸비 조회 + 프론트엔드 전체
**선행 필독** `dev-spec-00-shared.md`

> **당신이 만드는 화면이 데모에서 보이는 전부다.** 그리고 조회형 경로는 **LLM을 한 번도 거치지 않는다**(R9) — 인물·관계·용어·사건은 전부 DB 쿼리다. 상한은 쿼리 조건으로만 걸린다.

## 1. 프론트 불변식 — 이것 하나만 어겨도 게이트가 깨진다

**`page - 1`도 `%`도 프론트에서 계산하지 않는다.** 서버가 내려준 파생값을 그대로 렌더한다.

FR-BRF-005 🚦("대시보드 % · 브리핑 % · 싸비 기준점 불일치 0건")는 검증으로 맞추는 게 아니라 **계산 지점을 하나로 만들어 구조적으로 달성**한다(3.3절). 프론트에서 한 번이라도 재계산하면 그 순간 게이트가 무너진다.

세션 판정도 마찬가지다 — **클라이언트가 세션을 판정하지 않는다.** `POST entry`의 응답이 브리핑/읽기를 결정한다.

## 2. 단독 구간 — 시드로 끝까지 갈 수 있다

### S1. 조회 API ① `8/19`

| 엔드포인트 | 내용 | 근거 |
| --- | --- | --- |
| `GET /books` | 카탈로그 + **완비 여부** + (읽던 도서) 진도 파생값 | FR-BRW-001·002 |
| `GET /books/{b}/info` | `i` 팝업 — 기본 정보 / 소개 / 배경지식 **분리 필드** | FR-BRW-003 AC③ |
| `GET /books/{b}/pages/{n}` | 본문 단건. **진도 무관**(선요청 안전) | FR-PRG-001 |
| 목차 데이터 | 전체 장 상시 제공 | FR-NAV-001, R3 |

**배경지식·소개는 상한이 없다**(R5). 1페이지 시점에도 안전한 고정 콘텐츠이며, 안전 보증은 검수(R1)가 한다. 여기에 cutoff 필터를 걸지 않는다.

### S2. 화면 골격 + 라우팅 `8/19`

| 화면 | 핵심 |
| --- | --- |
| 대시보드 | 표지 그리드 · 읽던 도서만 진도 바+% · **미완비 도서는 표지만, 클릭 불가**(❓Q4) |
| `i` 팝업 | 3영역 **분리 렌더** — 혼합 금지 |
| 브리핑 | 리캡 / 빈 상태 · 목차+현재 장 강조 · 진도 바 · '마저 읽기' |
| 읽기 | 고정 페이지 + 페이지 내 스크롤 · **페이지 번호만**("12 / 340") |
| 싸비 사이드창 | 3탭 — 리캡 · 인물 관계도 · 챗봇 |
| 진입 라우터 | 서버 판정을 받아 라우팅 |

**미완비 도서의 클릭 불가는 UI 조치일 뿐이다.** 서버도 진입을 거절한다(R2, FR-BRW-002가 서버 차단을 요구). 둘 다 있어야 한다.

### S3. 읽기 화면 `8/19~8/20`

| 규칙 | 근거 |
| --- | --- |
| **페이지를 재분할하지 않는다.** 폰트·화면 크기 변화는 페이지 내 스크롤 길이만 바꾼다 | FR-PRG-001 |
| **진도 바 금지.** 페이지 번호만 표시 | FR-PRG-004 |
| 페이지 열림 확정 시 진도 이벤트 발신 (fire-and-forget, 넘김을 막지 않음) | NFR-PERF-005 |
| **페이지 내 스크롤은 이벤트를 만들지 않는다** | FR-PRG-003 AC④ |
| 목차는 이동 가능 (읽기 화면에서만) | UC-15 |
| 읽기 설정 | NFR-USE-004 |

**페이지 재분할 금지가 이 화면의 핵심 제약이다.** 페이지 번호가 곧 기준점의 단위이고 검색 청크의 단위이기도 하다(5.3절). 프론트가 화면 크기에 따라 페이지를 다시 나누면 시스템 전체의 좌표계가 무너진다.

### S4. 조회 API ③ + 관계도 `8/20`

**관계도 JSON** (`GET /books/{b}/ssabi/graph`)

| 규칙 | 근거 |
| --- | --- |
| 노드 = 인물 `최초 등장 페이지 <= K` | FR-SPL-002 🚦 |
| 별칭도 `별칭.최초 등장 페이지 <= K` 필터 | D6 |
| 간선 = 관계 `확립 페이지 <= K` 중 **최신 확립 페이지의 라벨 1개만** | A6, FR-CHR-001 🚦 (간선 중복 없음) |
| **간선은 양 끝 노드가 결과 집합에 있을 때만 반환** | FR-SPL-005 🚦 심층 방어 |
| 응답에 **페이지 값 포함** | NFR-OBS-003 |

**이력형 관계에서 최신 1개를 고르는 로직이 이 API의 함정이다.** 같은 쌍에 `(약혼, p.50)`과 `(부부, p.120)`이 있고 K=80이면 **약혼만** 나와야 한다. 최신을 무조건 고르면 누설이고, 전부 그리면 간선이 중복된다.

**인물 조회** (`GET /books/{b}/ssabi/characters/{c}`)

- 인물 노트를 `근거 페이지 <= K`로 필터해 이어붙인다
- 표시 상한: 최대 8문장, 초과 시 **최초 1문장 + 최근 7문장** (A5)
- 별칭 목록도 같은 필터
- **본문 인물명 탭과 노드 선택이 같은 응답을 쓴다** (FR-CHR-004·005)

### S5. 싸비 사이드창 `8/20`

| 규칙 | 근거 |
| --- | --- |
| 최초 열기 기본 탭 = **인물 관계도** | FR-SVB-002 |
| 페이지 변경 시 **열린 탭 재조회** | FR-SVB-003 |
| **탭 상태**: 세션 내 마지막 탭 유지, 새 세션이면 기본 탭으로 초기화 (경계 = 브리핑 경계) | FR-SVB-004 |
| 싸비 조작이 **본문 페이지 위치를 바꾸지 않는다** | FR-SVB-005 |
| 관계도는 서버 JSON을 그래프 라이브러리로 렌더, **라벨 병기**(색상 단독 구분 금지) | NFR-USE-006 |

### S6. 브리핑 화면 `8/20`

| 케이스 | 렌더 |
| --- | --- |
| 저장 리캡 있음 | 그대로 표시 |
| `recap: null` | 스트리밍 폴백 호출 |
| **첫 진입 (cutoff = 0)** | **"아직 읽은 내용이 없습니다"** — 폴백 호출하지 않는다 (❓Q1) |

| 규칙 | 근거 |
| --- | --- |
| 목차는 **표시 전용, 이동 불가** — 읽기 버튼을 만들지 않는다 | FR-BRF-004, D12 |
| '마저 읽기'는 **리캡 상태와 무관하게 즉시 동작** | UC-28 E1, FR-SPL-005 🚦 |

**브리핑 목차에 이동 기능을 넣으면 안 된다.** 프로토타입에 있던 "읽기" 버튼은 8/19에 제거로 확정됐다. 이동하면 기준점이 갱신되어 방금 표시한 리캡이 무효가 되고(R8), 브리핑에서 LLM 호출을 없앤 설계가 깨진다.

## 3. 결합 지점

### 🔗 R2의 API (8/19 계약, 구현은 나중)

`entry` / `progress` / `heartbeat` / `briefing` / `recap/stream`. **동결된 계약대로 목 응답을 만들어 진행**한다. R2 구현을 기다리지 않는다.

### 🔗 R3의 챗봇 SSE (8/20)

`POST /books/{b}/chat`. 스트리밍 형식을 R3와 맞춘다. 리캡 스트리밍(R2)과 같은 렌더 컴포넌트를 쓸 수 있다.

### 🔗 R1의 실데이터 (8/21)

시드에 **라벨이 바뀌는 관계 1쌍**이 들어 있으므로, 그전에 이력형 최신 라벨 선택 로직을 전부 검증할 수 있다.

## 4.5 자가 검증 — 화면으로는 안 보이는 것들

**조회형 버그는 화면상 티가 나지 않는다.** 관계도에 노드가 예쁘게 나오면 맞아 보이는데, 기준점 초과 간선이 하나 섞여 있어도 눈으로는 모른다. 테스트로만 잡힌다.

### 조회 상한 (FR-SPL-002 🚦)

| # | 테스트 |
| --- | --- |
| 1 | 관계도 응답의 모든 노드가 `인물.최초 등장 <= K` |
| 2 | 모든 간선이 `관계.확립 페이지 <= K` |
| 3 | 별칭 목록이 전부 `별칭.최초 등장 <= K` (D6) |
| 4 | 인물 노트가 전부 `근거 페이지 <= K` |
| 5 | **negative + positive 쌍** — 시드의 후반부 관계가 K=40에서 안 나오고 K=130에서 나온다 |
| 6 | **배경지식·소개는 K와 무관** (상한 예외 — R5) |

### 이력형 관계 (A6, FR-CHR-001 🚦) — 이 API의 함정

시드에 `(약혼, p.50)` / `(부부, p.120)` 쌍을 심어두고 확인한다.

| # | 테스트 | 기대 |
| --- | --- | --- |
| 7 | K = 80 | **약혼** 1개 (부부 아님) |
| 8 | K = 130 | **부부** 1개 (약혼 아님) |
| 9 | K = 40 | 간선 **0개** |
| 10 | 어떤 K에서도 같은 쌍의 간선이 2개 이상 나오지 않는다 | 중복 0 |

7번을 "최신을 고른다"로만 구현하면 K=80에서 부부가 나온다 — **누설**이다. 10번을 놓치면 간선이 중복된다 — **FR-CHR-001 위반**이다.

### 간선 무결성 (FR-SPL-005 🚦)

| # | 테스트 |
| --- | --- |
| 11 | 모든 간선의 **양 끝 노드가 결과 집합에 존재** |
| 12 | 인물 A는 보이는데 B가 안 보이는 K에서 A-B 간선이 **반환되지 않는다** |

12번이 심층 방어다. 관계 확립 페이지는 `<= K`인데 인물 B의 최초 등장이 `> K`인 상황이 데이터 오류로 생길 수 있다.

### 인물 노트 표시 상한 (A5)

| # | 테스트 |
| --- | --- |
| 13 | 노트가 8문장 초과일 때 **최초 1문장 + 최근 7문장** |
| 14 | 8문장 이하면 전부 표시 |

### 프론트 불변식

| # | 확인 | 방법 |
| --- | --- | --- |
| 15 | 프론트 코드에 `page - 1` · `/ total` · `Math.floor(...*100)` 패턴 **0건** | 정적 검색 (CI) |
| 16 | 대시보드 % · 브리핑 % · 싸비 기준점이 **같은 서버 값**에서 온다 | 응답 필드 추적 |
| 17 | 세션 판정 로직이 클라이언트에 **없다** | 정적 검색 |
| 18 | 페이지 내 스크롤이 진도 이벤트를 발생시키지 않는다 | 네트워크 탭 |
| 19 | 폰트·화면 크기를 바꿔도 **페이지 번호가 변하지 않는다** | 수동 |

19번이 FR-PRG-001의 핵심이다. 반응형으로 짜다 보면 자연스럽게 재분할하게 되는데, 그러면 시스템 전체의 좌표계가 무너진다.

### 브리핑 분기

| # | 테스트 |
| --- | --- |
| 20 | `cutoff = 0` → "아직 읽은 내용이 없습니다" 표시, **폴백 호출 안 함** (❓Q1) |
| 21 | `recap: null` (저장분 부재) → 폴백 호출 |
| 22 | 리캡이 실패해도 **'마저 읽기'가 동작** (UC-28 E1) |
| 23 | 브리핑 목차에 이동 가능한 요소가 **없다** (FR-BRF-004) |

20번과 21번을 같은 분기로 처리하면 첫 진입에서 LLM이 호출된다.

### 미완비 도서 (FR-BRW-002 🚦)

| # | 테스트 |
| --- | --- |
| 24 | 대시보드에서 클릭 불가 |
| 25 | **API를 직접 호출해도 서버가 거절** ← UI만으로는 부족하다 |

### 로그 (NFR-OBS-003)

| # | 테스트 |
| --- | --- |

## 5. 내가 실패하면 깨지는 게이트

| 게이트 | 내 몫 |
| --- | --- |
| FR-SPL-002 🚦 | 조회 상한 — 리포지토리 시그니처 `(도서, cutoff)` |
| FR-CHR-001 🚦 | 관계도 — 간선 중복 없음, 최신 라벨 1개 |
| FR-SPL-005 🚦 | 간선 양 끝 노드 검증 · 실패 시 미노출 |
| FR-BRF-005 🚦 | 프론트 재계산 금지 |
| FR-BRW-002 🚦 | 미완비 도서 클릭 불가 (서버 차단과 병행) |
| NFR-PERF-001·004·007 | 조회형 1.0/1.5초 · 관계도 1.5/2.0초 · 싸비 열기 1.0/1.5초 |
| NFR-OBS-003 | 조회 응답에 페이지 값 포함 — 없으면 FR-SPL-002 판정 불가 |

> **조회형은 캐시로 빨라지지 않는다.** 기준점이 사용자·위치별이라 응답 캐시 효율이 낮다. 저지연은 **인덱스 설계**로 달성한다(5.1.1절 — 페이지 PK 범위 스캔, 인물/관계의 위치 페이지 인덱스). 캐시를 붙이려다 상한이 섞이면 게이트가 깨진다.
