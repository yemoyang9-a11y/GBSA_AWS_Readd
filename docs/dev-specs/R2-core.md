## 2. 단독 구간 — LLM 없이 전부 가능

### S1. 기준점 결정기 `8/19`

```
저장값 (유일):  reading_position.current_page
파생 (결정기 전용 함수):
    cutoff  = current_page - 1              (FR-PRG-003 🚦)
    percent = current_page / total_pages    (MVP 1장)
    chapter = current_page가 속한 장          (장 경계 테이블)
```

**금지 사항** (3.3절)
- 다른 모듈·프론트에서 `page - 1`이나 `%`를 **재계산하지 않는다**
- 조회·조립 계층의 상한 파라미터는 **결정기 반환값 외의 원천을 갖지 않는다**
- **클라이언트가 "기준점"을 직접 보내는 API를 만들지 않는다** — 받는 것은 진도 이벤트뿐

**경계값** — `current_page = 1`이면 `cutoff = 0`. 싸비 정보 공집합, 리캡 입력 공집합, 챗봇은 배경지식 질의만 성립. **별도 분기를 만들지 않는다** — 같은 규칙이 자연스럽게 처리한다.

### S2. 진도 이벤트 + seq 순서 보장 `8/19`

`POST /books/{b}/progress` — `{page, seq}`

| 규칙 | 내용 |
| --- | --- |
| 비블로킹 | fire-and-forget. 페이지 넘김을 막지 않는다 (NFR-PERF-005, 300/500ms) |
| **순서 보장** | **더 새로운 seq일 때만 수용.** 빠른 연속 넘김·역방향 이동에서 이벤트가 역순 도착해도 저장 위치가 뒤로 밀리지 않는다 (FR-PRG-002) |
| 동기 커밋 | 수신 즉시 커밋. 클라이언트 미전송분의 손실 범위는 최대 페이지 1장 (NFR-REL-007) |
| 조회 요청의 동봉 | 싸비·리캡·챗봇 요청의 `(page, seq)`를 **진도 이벤트와 동일하게** 처리한 뒤 기준점을 파생. "페이지 넘긴 직후 싸비를 열었는데 저장이 아직 안 됨" 경합이 이걸로 닫힌다 |
| 페이지 조회와 분리 | `GET /pages/{n}`은 진도에 관여하지 않는다 — 선요청이 진도로 오인되면 안 된다 |

### S3. 진입 판정 + 하트비트 `8/19`

`POST /books/{b}/entry` → `{route: briefing | reader, page}`

- 세션 30분 규칙을 **서버가** 평가한다. 클라이언트가 세션 판정을 하지 않는다
- 미완비 도서는 진입 거절 (FR-BRW-002 — 서버 강제. 프론트의 클릭 불가와 **병행**)
- 판정 후 조작 시각 갱신
- 스위퍼 처리 여부와 **무관하게** `last_activity_at`에서 직접 평가한다. 스윕 지연이 브리핑 노출을 흔들면 안 된다 (FR-BRF-001 AC)

`POST /books/{b}/heartbeat` — 화면 가시 상태 5분 주기. 조작 시각 갱신 **전용**, 진도·기준점 비관여 (A2).

### S4. 세션 종료 스위퍼 `8/20` — 별도 실행 단위

```
조작 이벤트 수신 시:  last_activity_at = now, recap_state = 'none'

스위퍼 (스케줄, 주기 1분):
    대상 = recap_state='none' AND last_activity_at < now - 30분
    각 대상:
        cutoff 스냅샷 확보
        recap_state='pending' → 리캡 생성 잡 발행   (진도 무관 — R7)
        대화 이력 파기 (A7)   ← 질의 로그는 보존, 테이블이 다르다
```

**'조작'의 범위** (A2) — 서버 도달 이벤트 4종(진입 판정 · 진도 · 싸비 조회 · 리캡/챗봇 요청) + 가시 하트비트. **페이지 내 스크롤은 서버 이벤트가 없으므로 계상되지 않는다.**

**멱등·자기 교정 구조** — 오판정의 비용이 낮다. 세션이 일찍 닫혀도 해악은 "불필요한 LLM 1회 + 저장분 조기 갱신"뿐이고, 다음 조작이 오면 `recap_state='none'`으로 되돌아간다. 진행 중이던 잡이 뒤늦게 완료돼도 저장분의 기준점이 현재와 다르면 재사용 규칙(R8)이 자연 차단한다. **이 성질을 깨는 최적화를 하지 않는다.**

### S5. 리캡 입력 조립 `8/20` — LLM 없이 여기까지 가능

```
요청 → 기준점 스냅샷 K 확보
→ K = 0 (첫 진입) → 생성하지 않고 빈 상태 반환 (호출 0회, ❓Q1)
→ 재사용 판정:
    저장 리캡.기준점 == K  → 그대로 반환 (호출 0회, NFR-PERF-003)
    세션 캐시(K) 존재      → 그대로 반환 (호출 0회, UC-09 A7)
→ 조립:
    완결된 장 요약 = 장 경계.종료 페이지 <= K 인 장의 요약 전부
    현재 장 원문   = K가 장 중간일 때만, [현재 장.시작 페이지 .. K]
                    (K가 어느 장의 종료 페이지와 일치하면 원문 없이 요약만 — 중복 투입 방지)
→ LLM 1회 (스트리밍)  ← 여기만 R3의 게이트웨이
→ 세션 캐시(K) 적재 (영구 저장 없음, FR-DAT-010)
→ 로그: K, 투입 요약 ID, 절단 페이지, 출력 (NFR-OBS-002 🚦)
```

**상한은 입력 절단으로 강제한다. 프롬프트는 종합 지시만 담당한다**(FR-SPL-003 🚦, NFR-AI-004 🚦). "기준점 이후 내용을 쓰지 마"라는 지시로 막는 구조를 만들지 않는다.

**연결성 요구** (FR-RCP-003) — AC는 "독자가 기준점 직전에 읽은 내용"을 다루는 것이다. 장 첫 페이지 케이스는 예외로 분리하지 않고, 그 경우 **직전 장의 마무리**를 다루면 통과다. 조립 규칙상 직전 장 요약이 항상 투입되므로 별도 분기가 필요 없다.

### S6. 브리핑 조립 `8/20`

`GET /books/{b}/briefing` — 저장 리캡(기준점 일치 검증) + 목차 위치 + 진도 파생값

| 케이스 | 처리 |
| --- | --- |
| 저장분 유효 | 그대로 반환 |
| 저장분 무효·부재 | `recap: null` → 클라이언트가 스트리밍 폴백 호출 |
| **첫 진입 (cutoff = 0)** | **폴백 대상이 아니다.** 빈 상태로 응답, 클라이언트가 "아직 읽은 내용이 없습니다" 렌더 (❓Q1) |

**첫 진입과 저장분 부재를 같은 분기로 처리하면 안 된다.** 저장분 부재는 "만들 수 있는데 없는 것"이고, 첫 진입은 **만들 내용 자체가 없는 것**이다. 합치면 첫 진입에서 불필요한 LLM 호출이 발생한다.

**게이트 조항이 걸린 것은 구현 전에 테스트를 먼저 쓴다**(테스트 규약 3.2절). 테스트 이름에 조항 ID를 넣는다.

| # | 테스트 | 조항 |
| --- | --- | --- |
| 1 | 모든 페이지에서 `cutoff == current_page - 1` | FR-PRG-003 🚦 |
