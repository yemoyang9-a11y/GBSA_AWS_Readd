# 싸비(Reading Recap) — 개발 역할 분담 · 작업 순서 · 중간점검

**근거 문서** `architecture-r1.md` v0.9 · `decisions-0819-final.md` (D1~D13)
**기간** 8/19 착수 → **8/22 MVP Freeze** → 8/28 발표
**인원** 4명 · **범위** 「탁류」 1권, 데모 필수 경로만

> 아래 배치는 **아키텍처 3.2절 컴포넌트 경계와 4.3절 의존 규칙**을 그대로 절단선으로 삼았다. 개인별 기술 스택은 이 문서의 입력이 아니므로, 사람 배정은 팀이 조정한다.

## 0. 배치의 원칙

| 원칙 | 이유 |
| --- | --- |
| **한 게이트의 강제 지점은 한 사람 안에 둔다** | 게이트 강제가 두 사람에게 갈리면 "누가 상한을 거는가"가 흐려진다. 기준점 결정기(②)와 근거 조립(⑤)을 다른 무엇과도 합치지 않은 아키텍처 2장의 판단을 사람 배치에도 적용 |
| **파이프라인은 전담 1명** | ⑦의 산출물이 ③④⑤ 전부의 입력이다. 겸임시키면 다른 작업에 밀려 전원이 대기한다 |
| **조회 API와 화면은 같은 사람** | ③의 JSON 계약과 렌더가 한 세트다. 프론트 불변식(파생값 재계산 금지, 4.1절)을 같은 손이 지키는 편이 확실하다 |
| **상한 강제 3경로는 교차 리뷰** | NFR-SEC-006 판정 ①이 "코드 작성자 외 1명 리뷰·기록"을 요구한다(5.4절). 배치 단계에서 리뷰 짝을 미리 정해둔다 |

## 1. 역할 분담

### R1 — 데이터·파이프라인 `⑦ + 검수`

| 담당 | 근거 조항 |
| --- | --- |
| 원문 등록 · **페이지 분할**(목표 1,000자 / 700~1,400 / 장 경계 절대) | FR-ADM-001·002, D11 |
| 장 경계 매핑 + **커버리지 검증** | FR-DAT-001·002 🚦 |
| 생성 6종 순차 실행 · 재시도 · 알림 (장 요약 / 인물·별칭 / 관계 / 배경지식·소개 / 용어 / 사건) | FR-ADM-003·004, NFR-AI-015 |
| 전 산출물 **위치 페이지 태깅** (별칭 최초 등장, 관계 확립 페이지, 인물 노트 근거 페이지) | D6, A5, A6 |
| 페이지 임베딩 배치 적재 (Titan V2) | 5.3절 |
| 검수 시트 내보내기·반영 · **공개 전환** | FR-ADM-005 🚦·006, NFR-AI-011 🚦 |
| 시연 위치 리캡 주입 스크립트 | UC-19 3번 |
| **실측 3건 보고** (글자 수 분포 / 문장 폴백 빈도 / 가장 긴 장의 절단 최대 크기) | 4.4.2절 |

**이 역할이 막히면** 전원이 시드 데이터에 머문다. 8/19~8/20이 이 사람의 최우선 구간이다.

---

### R2 — 코어 상태·리캡 `② + ④ + 스위퍼`

| 담당 | 근거 조항 |
| --- | --- |
| **기준점 결정기** — 유일 계산 지점, 스냅샷 반환 | FR-PRG-003 🚦, FR-BRF-005 🚦 |
| 진도 이벤트 `{page, seq}` · **seq 순서 보장** · 비블로킹 | FR-PRG-002, NFR-PERF-005 |
| 진입 판정(`POST entry`) — 30분 규칙, 브리핑/읽기 라우팅 | FR-BRF-001 |
| 하트비트 수신 (5분, 조작 시각 갱신 전용) | A2 |
| **세션 스위퍼** (1분 주기, 대화 이력 파기) | A3, A7 |
| 리캡 종합 코어 — 입력 절단 조립, LLM 1회 | FR-SPL-003 🚦, NFR-AI-004 🚦 |
| 재사용 판정(기준점 완전 일치) · 세션 캐시 · 저장 리캡 upsert | FR-DAT-009·010, R8 |
| 브리핑 조립 — **첫 진입은 빈 상태**(cutoff = 0, 폴백 없음) | ❓Q1 확정, D13 ① |
| 리캡 호출 로그 | NFR-OBS-002 🚦 |

**②와 ④를 묶은 이유** — 스위퍼가 세션 종료를 판정해 리캡 잡을 발행하는 흐름이 한 덩어리고(4.4.1절), 둘 다 cutoff를 중심으로 돈다. 분리하면 세션 상태와 리캡 상태가 두 사람 사이의 계약이 된다.

### R3 — AI 경로 `⑤ + ⑥`

| 담당 | 근거 조항 |
| --- | --- |
| **LLM 게이트웨이** — 작업별 모델 매핑(**설정 분리**), 버전 고정, 재시도, 스트림 패스스루, 토큰·실패율 계측 | NFR-AI-001·002·003, NFR-OBS-004 |
| 호출량 상한 — **디바이스·도서당 분당 3회** | NFR-AI-017, A1 |
| **근거 조립기** — 전량 주입 ①②③ + 검색 청크, 질의 텍스트 비관여 | FR-QNA-006 🚦 |
| 벡터 검색 — `page_no <= K` **사전 필터**, top-N 6 | 5.3절, D11 |
| **난이도 분기(규칙 기반)** — 복잡 Sonnet / 그 외 Haiku, LLM 라우팅 금지 | D13 ②, R9 |
| 근거 부재 토큰 감지 → **서버 상수 문구 치환** | FR-QNA-004 🚦 |
| 챗봇 질의 로그 — 투입 레코드 전수 + 검색 선정 페이지 + 선택 모델 | NFR-OBS-005 🚦 |

**게이트 밀도가 가장 높은 역할이다.** FR-QNA-006, FR-QNA-004, NFR-SEC-006, NFR-OBS-005가 전부 여기서 강제된다.

### R4 — 프론트엔드·조회 `① + ③ + 화면 전부`

| 담당 | 근거 조항 |
| --- | --- |
| 대시보드 — 표지 그리드, 진도 바(서버 파생값 렌더), **미완비 클릭 불가** | FR-BRW-001·002, ❓Q4 |
| `i` 팝업 — 3영역 분리 | FR-BRW-003 |
| 브리핑 화면 — 리캡/빈 상태, 목차 **표시 전용**(읽기 버튼 없음), '마저 읽기' 독립 동작 | FR-BRF-002~005, D12 |
| 읽기 화면 — 고정 페이지, 페이지 번호만(진도 바 금지), **재분할 금지**, 진도 이벤트 발신 | FR-PRG-001·004 |
| 싸비 사이드창 3탭 — 기본 탭 인물 관계도, **탭 상태 유지**(세션 경계 초기화), 페이지 변경 시 재조회 | FR-SVB-002·003·004 |
| SSE 스트리밍 렌더 (리캡·챗봇) | NFR-PERF-002 🚦·008 |
| ① 카탈로그 · 페이지 단건 · 목차 · 배경지식/소개 | FR-PRG-001, FR-NAV-001 |
| ③ 관계도 JSON 조립 — **이력형 최신 라벨 1개**, 간선 양끝 노드 검증 | FR-CHR-001 🚦, A6, FR-SPL-005 🚦 |
| ③ 인물 맥락 설명 + 별칭 목록 (`<= 기준점` 필터) | FR-CHR-004·005 |

**프론트 불변식 하나만 기억하면 된다** — `page − 1`도 `%`도 프론트에서 계산하지 않는다. 서버가 내려준 값을 그대로 렌더한다(3.3절 금지 사항).

| 2 | **기준점 스냅샷 인터페이스** — `{ current_page, cutoff, percent, chapter }` 반환 시그니처 1개 | 3.3절, 4.3절 |

### 시드 데이터 (동결과 함께)

파이프라인 완주 전에 R2·R3·R4가 놀지 않으려면 **손으로 만든 소량 데이터**가 필요하다. 3~5장 분량이면 충분하다 — 페이지 20~30개, 인물 5명, 별칭 10개, 관계 5개(그중 1개는 이력형 2행), 장 요약 3개, 용어·사건 각 5개, 배경지식 1개.

**시드에 반드시 포함할 것** — ① 확립 페이지가 뒤쪽인 관계 1개(스포일러 차단 확인용) ② 후반부에 처음 나오는 가족관계 호칭 별칭 1개(D6 확인용) ③ 라벨이 바뀌는 관계 1쌍(A6 확인용). 이 세 개가 없으면 상한 로직이 동작하는지 눈으로 볼 수 없다.

## 4. 중간점검 (7회)

각 점검은 **통과 조건이 있는 게이트**다. 진척 보고가 아니라 판정이다.

### CP0 · 8/19 오전 — 계약 동결
**통과** — 2장의 4개 항목 + 시드 데이터가 저장소에 올라가 있다.
**실패 시** — 병렬 착수를 미루고 동결을 끝낸다. 여기서 아낀 시간은 통합에서 몇 배로 나간다.

### CP1 · 8/19 저녁 — 분할 실측 (D11 검증)
**통과** — R1의 실측 3건 보고. 700자 미만·1,400자 초과 비율, 문장 폴백 빈도, **가장 긴 장의 절단 최대 크기**.
**판단** — 문장 폴백이 잦으면 상한을 1,600자로 완화(D11 기록된 대응). 가장 긴 장의 절단 크기는 그대로 **NFR-PERF-008 예산의 입력**이므로 R3에 전달한다.

### CP2 · 8/20 저녁 — 경로별 단독 동작 (시드 기준)
**통과 4건** — ① 페이지 넘김에 cutoff가 따라온다 ② 리캡이 스트리밍으로 나온다 ③ 챗봇이 근거 안에서 답하고 밖은 통일 문구로 거절한다 ④ 관계도가 렌더된다.
**핵심 확인** — 시드에 심어둔 후반부 관계가 **앞 기준점에서 안 보이는가.** 이게 이 프로젝트의 본질이다.

### CP3 · 8/21 저녁 — 관통
**통과** — 대시보드 → 브리핑 → 읽기 → 싸비 3탭이 한 번에 흐른다. 세션 30분 규칙과 브리핑 경유/생략이 동작한다.
**함께 확인** — 첫 진입 시 브리핑이 뜨고 리캡 자리에 "아직 읽은 내용이 없습니다"가 표시되며 **LLM 호출이 0회**인가(D13 ①).

### CP4 · 8/22 Freeze — 강제 지점 검증
**통과 3건** — ① 실데이터로 전 기능 동작 ② 교차 리뷰 3경로 기록 완료(NFR-SEC-006 판정 ①) ③ 로그에 투입 레코드·검색 선정 페이지가 전수 남는다.
**기능 동결.** 이후 변경은 결함 수정만.

### CP5 · 8/25 — 게이트 판정 1차
**통과** — 리그레션 30건 0건 누설, 인젝션 10건 초과 레코드 0건, 응답 확인 0건.
**미달 시** — 남은 3일이 수정 여유다. 이 점검을 8/27로 미루면 고칠 시간이 없다.

### CP6 · 8/27 리허설 — 재실행
**통과** — 성능 3지점 재측정(발표장 네트워크), 인젝션 10건 재실행, **같은 질문 반복 실행**(A10 — 1회 통과를 근거로 삼지 않는다).
**함께** — 시연 위치 리캡이 주입돼 있어 정상 동선에서 실시간 호출이 0회인가.

## 5. 선행 관계에서 나오는 병목 3가지

문서에 이미 기록된 종속이며, 일정 우려가 아니라 **순서상의 사실**이다.

| # | 병목 | 대응 |
| --- | --- | --- |
